# 踩坑卡片库

每张卡片格式：**现象 → 成因 → 检测 → 修复 → 实例**。
卡片 ID 用于跨会话引用（例如「这是 CI-002 那张卡」）。

**元数据口径**（每卡第一行是 `> 元数据：…`）：

| 字段 | 含义 |
|---|---|
| `date` | 首次收录日。本库首版统一记 2026-10-16（以原件文件时间戳为准）；案例自身发生日期写在「实例」里 |
| `version` | 卡片修订号，内容实质改动一次 +1 |
| `confidence` | `high` = 规范/标准原文或机制必然；`medium` = 实证但样本单一、或阈值靠经验；`low` = 经验归纳、未做对照 |
| `invalid-when` | 这条在什么条件下不成立（写结论前必须检查） |
| `counter-example` | 一个反例或边界情形，防止把卡片当教条 |

## CFG-001 · YAML 1.1 布尔字面量陷阱

> 元数据：date 2026-10-16 · version 1 · confidence high（YAML 1.1 规范原文） · invalid-when 解析器为 YAML 1.2，或显式用 failsafe schema · counter-example 键值都加引号时解析为字符串，「陷阱」不成立

**现象**：配置项写对了，但运行时完全不生效，没有任何报错。

**成因**：YAML 1.1（js-yaml 默认 schema、Ruby/Python 老式 loader 等）会把下列**未加引号**的裸词解析成布尔值：

```
y / Y / yes / Yes / YES / n / N / no / No / NO / true / false / on / On / ON / off / Off / OFF
```

于是 `off: off` 会被解析成 `{false: false}` —— 键变成了布尔 `false`，而不是字符串 `"off"`。
配置解析器按字符串键查找时找不到，该项静默失效。

**检测**：

```bash
python3 - <<'PY'
import yaml, json
d = yaml.safe_load(open('<配置文件>'))
def walk(o, p=''):
    if isinstance(o, dict):
        for k, v in o.items():
            if isinstance(k, bool) or isinstance(v, bool):
                print(f'  布尔化: {p}.{k!r} = {v!r}')
            walk(v, f'{p}.{k}')
walk(d)
PY
```

**修复**：**给这类键和值都加引号** —— `"off": "off"`。
更稳的做法：整个映射的键统一加引号，或改用 YAML 1.2 解析器（1.2 已移除 on/off/yes/no）。

**实例（CI-002 的现场）**：某配置里 `opendesign` 段的档位映射写成
```yaml
off: off        # ← 未加引号
low: low
```
实测解析结果为 `{false => false, "low" => "low", ...}`，`off` 档位实际不可用。
改成 `"off": "off"` 后恢复正常。

## CFG-002 · 模型缺少 `input` 声明导致读图被拒

> 元数据：date 2026-10-16 · version 1 · confidence high（机制明确 + 同通道对照实证） · invalid-when 网关本身不支持图像，补 `input` 只是把拒图从声明层推迟到网关层 · counter-example 声明了 `input` 仍被拒的通道

**现象**：`read_image` / `view_image` 一律失败，报错形如
`model "X" does not declare image input; switch to an image-capable model`。

**成因**：**关键字是 declare（声明）**。Agent 在发图前检查的是**配置里的 `input` 列表**，
不是模型的真实能力。配置项缺 `input` 字段（或只写了 `text`），Agent 就拒绝发图。

**检测**：查配置里该模型是否声明了图像输入：

```yaml
- id: <模型>
  input:
    - text
    - image     # ← 缺这一行就会拒图
```

**修复**：补上 `input: [text, image]` 后重启 Agent。
**注意**：补上后能否真的读图，取决于上游网关是否支持，需实测验证。

**实例**：同一中转站通道下，`DeepSeek-V4.1-Flash` 配置无 `input` 字段 → 4/4 读图失败；
同通道的 `gpt-6-astra`、`gpt-6.1-sol` 声明了 `input: [text, image]` → 4/4、2/2 成功。
**结论**：这既不是「通道不行」也不是「模型不行」，而是**配置声明缺失**。

## CFG-003 · `contextWindow` 是声明值，不等于真实上限

> 元数据：date 2026-10-16 · version 1 · confidence medium（单厂商单模型实测） · invalid-when 网关按声明足额分配上下文 · counter-example 实测上限等于声明值的模型

**现象**：长会话跑到一半突然硬失败，而不是触发提前压缩。

**成因**：`contextWindow` 是本地声明的数字，网关可能只给更小的真实上限。
声明虚高时，Agent 的压缩触发点会晚于网关的硬上限。

**检测**：故意灌入接近声明值的上下文，读网关的报错原文，例如
`876739 tokens > 872000 maximum context length` → 真实上限是 872,000。

**修复**：把 `contextWindow` 改成实测值。并**对其余模型逐个实测** ——
同一批配置里往往存在多个「整数感很强」的可疑值（1048000 / 1050000 / 1100000）。

**实例**：某模型对外标称 1.1M 上下文，实测上限 872,000（**79%**）。
另注：查网关的 `/v1/models` 接口发现它**根本不返回 `context_length` 字段**
（只有 `id` 与 `owned_by`，且把所有模型一律标成 `owned_by: "openai"`）——
**宣传页上的数字在 API 层面无法自证**，这类元数据不应作为配置依据。

## CFG-004 · `max_tokens` 对部分模型不生效

> 元数据：date 2026-10-16 · version 1 · confidence medium（部分网关） · invalid-when 该网关确实执行 `max_tokens` · counter-example `max_tokens=1` 时确实只输出 1 token

**现象**：配置了输出上限，但模型照样输出远超该值。

**成因**：部分网关/模型忽略该参数。

**检测**：把 `max_tokens` 设为 1，发一个必然长输出的请求。若仍输出上千 token → 参数无效。

**修复**：不要依赖它控成本；改用提示词约束或缩短任务粒度。

## CI-001 · 同一台机器上不同 Agent 读不同的规则文件

> 元数据：date 2026-10-16 · version 1 · confidence high（机制必然 + 可复现） · invalid-when 两个外壳读同一份文件、或共用同一条注入通道 · counter-example 两份文件逐字相同

**现象**：同一个模型，换个 Agent 就跑出完全不同的行为。

**成因**：不同 Agent 从不同路径加载行为规则，例如：

| Agent | 读取位置 |
|---|---|
| Codex | `~/.codex/AGENTS.md`（且可能同时读 `~/AGENTS.md`） |
| DeepSeek Harness | `~/AGENTS.md` |
| 其他 | 各自的 `AGENTS.md` / `CLAUDE.md` / 配置项 |

两份文件内容不同 → 同一模型行为分叉。

**检测**：从会话记录里提取实际注入的规则文本，**逐字比对**（不要比文件名）：

```python
# Codex：session_meta.payload.base_instructions + user message 里的 AGENTS.md 段
# DSH ：user/message 中 source.kind == 'agent-instructions'
```

**修复**：确立**唯一权威版本**，其余位置用同步脚本保持一致。
**副作用警告**：统一规则后，**统一之前的历史运行数据可比性被破坏**，
排名/对比表里必须标注「该批数据产生于旧规则下」。

## CI-002 · YAML 布尔陷阱的现场复现：`off: off` 让整个档位静默失效

> 元数据：date 2026-10-16 · version 1 · confidence high（规范原文 + 现场复现） · invalid-when 键已加引号，或解析器为 YAML 1.2 · counter-example 用 JSON 写配置

**现象**：配置里写了一个档位映射，代码按字符串键去取，`off` 档永远取不到值；不报错、不告警，只是「这个档位好像不存在」。

**成因**：CFG-001 的实例化。`off: off` 两个 `off` 都没加引号 → 键和值都被解析成布尔 `false`，映射实际得到 `{False: False}`，而字符串键 `"off"` 不存在。

**检测**：

1. 解析后把整张映射 dump 出来，看键的类型是不是 `bool`；
2. 或直接断言 `"off" in cfg['providers'][p]['reasoningEfforts']`。

**修复**：`"off": "off"`（键和值都加引号）。

**实例（本机实测）**：某 provider 的档位映射写成

```yaml
off: off
low: low
```

实测解析结果为 `{False: False, 'low': 'low'}`，`off` 档不可用；改引号后恢复。

**教训**：「配置写了但不生效」优先怀疑 YAML 布尔化，而不是先怀疑代码。

## CI-003 · 「关键路径不许简化」但枚举范围不含本任务领域

> 元数据：date 2026-10-16 · version 1 · confidence medium（经验归纳） · invalid-when 规则另有兜底句（如「凡不可逆操作一律…」） · counter-example 模型主动做了领域交集判断

**现象**：规则里明明有「禁止用近似替代精确计算」，模型还是用了近似画法。

**成因**：该条款枚举了适用范围（如「数据一致性、金额/资金、安全校验、性能关键路径」），
**本任务领域不在列举内**，按字面读不会触发。

**检测**：把规则里所有「限制性条款」的**枚举范围**与当前任务领域做交集，交集为空即为本坑。

**修复**：在枚举里显式加上本领域，并点名「本条最常在这里翻车」。
**通用教训**：**限制性规则必须显式枚举适用领域，否则等于没有。**

## CI-004 · 「留一个最小的检查」被理解为「只查容器格式」

> 元数据：date 2026-10-16 · version 1 · confidence medium（单模型两外壳，n=2） · invalid-when 规则已明确要求内容断言覆盖度 · counter-example 容器断言很少、内容断言充足的脚本

**现象**：脚本自检全绿，但领域内容错了一大片。

**成因**：规则写的是「留**一个**最小的可运行检查」—— 这是**最小预算**。
模型会把这个预算花在**最容易写、最容易通过**的地方：文件格式、编码、尺寸。
内容层面的正确性反而无人检查。

**检测**：把脚本里的 `assert` 分类统计：
- **容器类**：magic bytes、bit_depth、行数列数、取值集合、放大倍率……
- **内容类**：领域语义断言（例：「这里应该是陆地」「这里应该是水」）

若容器类 ≫ 内容类（尤其内容类 = 0），即为本坑。

**修复**：把自检要求写成**覆盖度要求**而不是**数量要求**：
「每个大区都必须有断言点，且同一区域必须同时有『期望是』与『期望不是』的断言」。

**实例**：同一模型两个外壳的对比 ——
A 的脚本 17 条 assert **全是 PNG/CSV 格式校验**（`data[:8]==b'\x89PNG'`、`block == value*255` …），内容断言 **0 条** → 得分 86.30%；
B 的脚本有 **48 条分区双向地理断言** → 得分 94.35%。
误差分布印证：改善集中在**有断言覆盖**的区域（非洲 FP 291→跌出前 6、亚洲 FN 96→7），
而两边都没细分覆盖的区域（北极圈）几乎没改善（429→361 格）。

## CI-005 · 只有容器断言、没有内容断言

> 元数据：date 2026-10-16 · version 1 · confidence high（变异测试的必然推论） · invalid-when 领域数据被换错时脚本确实会失败 · counter-example 带内容断言的测试集

同 CI-004 的检测与修复。单列一张卡是因为它是**最高频的隐性失效**：
所有检查都通过、日志全是绿色，但产出在领域上是错的。

**一句话判据**：**「如果把这个脚本的领域数据全换成错的，它还会自检通过吗？」**
会通过 → 你的自检没有覆盖领域内容。

## CI-006 · 推理档位提高 ≠ 质量提高

> 元数据：date 2026-10-16 · version 1 · confidence medium（n=2，单模型） · invalid-when 验收标准同步提高 · counter-example 提高档位后得分单调上升的任务

**现象**：把 reasoning effort 调到最高，得分反而更低。

**成因**：档位只控制**思考预算**，不控制**验收标准**。预算用在哪由规则和自检要求决定。
预算翻 10 倍但验收标准不变时，多出来的思考会被花在同样不检查的地方。

**检测**：从会话的请求头/`turn_context` 里取实际 `effort`，与得分对照。

**修复**：先补验收标准，再考虑加预算。

**实例**：同一中转站模型，A 用 `xhigh`（推理量约为 `high` 的 10 倍）得 86.30%；
B 用 `high` 得 94.35%。**A 拿了 10 倍预算反而低 8 分。**

## MEM-001 · 长期记忆把上一次的复盘摘要注入下一次「独立完成」任务

> 元数据：date 2026-10-16 · version 1 · confidence medium（存在性证据 + 单次实例） · invalid-when 记忆条目与该任务领域无关，或已关闭召回 · counter-example 注入里只有通用偏好、无任务相关内容

**现象**：题目要求「独立完成、不借鉴任何现有作品」，但模型开工前就拿到了上一次的复盘。

**成因**：Agent 的长期记忆会自动把已完成任务总结成条目，并在**下次相似任务**开工时召回注入。
条目里常含：上一次的文件路径、方法、口径、**踩过的坑与修法**。

**检测**：查开工前的 `dsh-session-kit-memory-context`（或同类）注入内容，
对**领域关键词**做计数；命中后进一步比对本次产物与上次产物的具体数值/结构。

**修复**：
- 做这类测试前**删除该领域记忆条目或关闭会话记忆**；
- 或把记忆条目的召回范围限定到「非独立任务」。

**实例**：某次运行的记忆注入里含上一条世界地图条目，泄露了上轮脚本路径、
方法口径，以及两处 bug 签名（「某多边形自交」「某测试点坐标要改」）。
经比对**未发生答案级转移**（本次多边形与上轮完全不同），但**该次成绩的独立性已被削弱**。

## MEM-002 · 记忆污染是滚雪球的

> 元数据：date 2026-10-16 · version 1 · confidence low（推论，未做对照） · invalid-when 记忆条目有 TTL 或人工复核 · counter-example 第二次运行的注入里已无该领域条目

**现象**：第一次运行干净，此后每一次都「恰好」知道上一次的坑。

**成因**：条目一旦生成，就会持续被后续相似任务召回。

**检测**：按时间顺序列出各次运行的注入内容，看该领域条目**从哪一次开始出现**。

**修复**：越早清理越好；已产生污染的历史数据需标注。

## QA-001 · 验证「是否作弊」的判据优先级

> 元数据：date 2026-10-16 · version 2（第 1 条措辞降级） · confidence medium（优先级是判断，不是定理） · invalid-when 被审对象能改写自己的历史记录 · counter-example 只有 L4 物证却写成 L1 级结论

按可信度排序，**从上往下做**：

1. **隔离重跑取哈希**（最强）：空目录 + 仅脚本 + `python3 -S -B` 重跑，逐位比对 sha256。
2. **脚本静态审计**：外部数据读取点；**坐标小数位分布**（手写 vs 数据集的最强指纹）。
3. **工具调用审计**：是否读了题目以外的文件（注意 `custom_tool_call` 也要统计）。
4. **注入上下文审计**：记忆 / 技能 / 规则是否夹带了答案。
5. **误差形态分析**：连通块尺寸区分「手绘」与「数据降采样」。
6. **横向比对**：与磁盘上其它产物的相似度（若接近 100% 才是抄袭）。

**注意**：第 1 条排除的是「运行时外部读取」——哈希一致只说明产物是脚本的确定性函数。
它**排除不了**编译期硬编码、把数据集内联进脚本、或照抄一份现成产物。
结论写「未排除编译期硬编码」，**不写「作弊在物理上不可能」**。

## QA-002 · 采样点落在网格边界上导致射线法退化

> 元数据：date 2026-10-16 · version 1 · confidence medium（可复现的几何退化） · invalid-when 采样点远离边界、或无射线法 · counter-example 平移采样点后判定结果不变

**现象**：多边形自检「无自交」，但个别格点判定异常。

**成因**：采样点**恰好落在多边形的边或顶点上**，射线法的奇偶规则出现退化。

**检测**：全量扫描 16,200 个点，断言「没有任何点落在边或顶点上」。
不要靠微扰单个顶点（会把边界点推出去），要**平移采样点**一个极小量（如 1.2e-4°）。

**修复**：平移采样点 + `assert_no_edge_hits()` 全量扫描。

## QA-003 · 断言必须双向

> 元数据：date 2026-10-16 · version 1 · confidence high（测试理论必然推论） · invalid-when 双向断言本身写反 · counter-example 单向断言却抓到了 bug（说明断言方向与 bug 相反）

**现象**：自检全绿，但一大片区域整块判反了。

**成因**：检查集只断言了**一个方向**。例：南极只断言「这些点是水」——
而 bug 恰恰让它们变成水，于是**断言因为 bug 本身而全部通过**（确认偏误测试集）。

**修复**：同一区域必须**同时**有「期望是」与「期望不是」的断言。

**实例**：某脚本 304 个检查点里，纬度 ≤ −60 的只有 5 个且**全部期望为水**；
纬度 ≥ 72 的 **0 个**。结果整块南极被误判为水，自检却全绿。

## QA-004 · 断言必须按区域配平

> 元数据：date 2026-10-16 · version 1 · confidence medium（方向对，阈值靠经验） · invalid-when 任务只关心单一区域 · counter-example 断言堆在城市、而错误也只在城市

**现象**：断言数量很多，但错误集中在没被覆盖的区域。

**成因**：检查点「堆城市名」——容易想到的地方堆了几百个，两极/大洋 0 个。

**修复**：按大区配平，**每个大区（含两极与各大洋）都必须有断言点**。

**判据**：断言数量不是关键，**分布才是**。
反面证据：某脚本有 304 条断言却只拿 83.10% —— 因为最需要覆盖的两极是空的。

## QA-005 · 用 `-S` 复现同时证明「无第三方依赖」

> 元数据：date 2026-10-16 · version 1 · confidence high（`-S` 语义确定） · invalid-when 脚本用内置模块伪装外部依赖，或产物依赖系统库 · counter-example 脚本 import 三方可复现通过

复现时用 `python3 -S -B <脚本>`：

- `-S` 不加载 site-packages → 脚本若偷偷 `import numpy`/`PIL` 会立刻失败；
- `-B` 不写 `__pycache__`，保持目录干净。

配合「隔离目录里只有脚本一个文件」，可同时排除**第三方依赖**与**外部数据**两种可能。
